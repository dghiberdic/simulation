# Spec audit: `sim/` against `Project Round 2 Spec.md` (13 October 2026)

This audit checked branch `audit-logging`, which starts from `spec-0810` at 740ecb0. The authority is `Project Round 2 Spec.md`; it is byte-identical to `v5_work/spec_v5.md`.

## Method

Six auditors each read one slice of the spec and traced it into the code:

| Auditor | Spec sections |
|---|---|
| A1 | §2–§4 |
| A2 | §5.1–§5.3 |
| A3 | §5.4 and §6 |
| A4 | §7–§8 |
| A5 | §9, resume and budget |
| A6 | Appendix A, word for word |

Each auditor proved every suspicion with a probe test (`sim/tests/audit/test_probe_A*.py`). Two more agents then tried to refute each finding; they read the spec in context, the git history, and the tests that already pin behaviour.

**Outcomes:**
- **Confirmed:** fixed in code, and its probe now passes.
- **Spec question:** the code looks deliberate or defensible, so the spec text should change. The code is kept and the probe is marked `xfail(strict=True)` with the reason. If the behaviour ever changes, the xfail flips and the suite says so.
- **Refuted:** no deviation, or the probe was wrong. The probe is kept as `xfail` with the reason.

**Bottom line:**
- **Prompts:** every Appendix A text the seats receive is verbatim, with placeholders filled. No leaks were found: run length, final turn, juries, odds, the experiment, other conditions and hidden ledgers are all absent.
- **Core mechanics:** the economy, the §4 seeds, intrusion, whistleblowing, juries and scoring match the spec. Hand calculations were checked against the code.
- **Findings:** 9 were fixed and 15 are open for a decision.

## Open: spec questions for David

The code is unchanged for all of these. Each one needs either a spec edit or a decision.

| ID | Spec text | What the code does | Suggested spec change |
|---|---|---|---|
| A1-1 | §3.3 "every action costs at least 1 Capital or Influence" | The minimum is checked on the purchase as submitted. A pro-rated purchase is charged for the granted units only, which can be less than 1, or 0. §3.1 and §5.3 already sanction pro rata. | "…as submitted; a pro-rated purchase pays for the units granted." |
| A1-3 | §3.3 the cap "binds by turns 2–3" | Headroom on turn 1 is 149 units and five maximum purchases ask for 150, so the cap binds on turn 1 if everyone buys the maximum. | "can bind from turn 1 if every lab buys its maximum." |
| A1-4 | §2 "each seat picks its value at its first prompt" | The value is taken at the first decision prompt. In T4 (separate) the offer and reply rounds come first, and the pilot has no turn-1 value pull. This is pinned by `test_engine_flow.py:468`. | "at its first decision prompt; no value pull on turn 1 of a pilot run." |
| A1-6 / A5-5 | §2 "each seat is also told its judged pilot value" | When T2 fails, the seat is told its median chosen value (step 2 of §2). | "…told its T2 value as its setting." |
| A2-3 | §5.3 "a true tip naming one committer" | A tip names an unexposed committer only, so if all committers were caught, no tip is sent. | "naming one unexposed committer." |
| A2-4 | §5.2: simultaneous proposals, one execution step | Effects apply in lab order. Order matters only near limits: `lobby_institution` within 1 point of a lab's own value, and `publish_narrative` at 0 or 100. | State "effects apply in lab order", or define a simultaneous rule (sum the deltas, clamp once). |
| A2-6 | §5.3 joint intrusions, A.8 partner reports | If all of the accused's parts are penalised, a report matches the earliest one. If that part is solo, the reporter's own later joint part is not self-reported. | Say which penalised part a returned report matches, or prefer a part the reporter shares. |
| A4-1 | §5.4 "the Grand Jury reads … private sheets" | The juror never sees a seat's four true values. Showing them alongside the state values would let it work out the disposition it rates blind (§7). | "…private sheets (true values withheld, for blinding)." |

| A6-1 | Appendix A "items already issued (marked as earlier)" | This month's items are marked `[new]` (pinned by `test_seat_text.py:163`). | "…with this month's items marked [new]." |

| A6-6 | Appendix A prompt order | The engine puts a "{lab}'s charter: {name}" heading before the charter. | List it as engine-generated. |

## Refuted

| ID | Claim | Why it was refuted |
|---|---|---|
| A1-2 | A chosen disposition is rounded twice | The reply schema asks for an integer. The integer played is then rounded to 10 once (pinned by `test_prompts.py:548`). |
| A1-5 | Main runs accept values not rounded to 10 | `dispositions.json` is written only by `tools/disposition.py`, which rounds. A hand edit is operator error. Adding a check would be optional hardening. |
| A2-2 | A second intrude acts as a fall-back | Only one intrude is ever carried out in a month, and A2-1 now limits a seat to its first two submitted actions. |
| A4-2 | Exact ties get different ranks | The spec says nothing about ties. Seats see shared ranks on the ledger, and exact float ties occur only at t=0. |
| A4-4 | The mandate filter misses "use another lab's compute" | The language-model screen, which fails closed, names this case. Only the keyword pre-filter and the offline stub miss it. |
